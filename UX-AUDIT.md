# Hearth UI/UX audit · Run 39

The review prioritizes 390×844 iPhone WebKit in dark mode. It also covers 375×667 and 1440×1000 in both themes. The disposable workspace uses 14 threads, long titles and replies, 16 artifacts including a Page, an approval, an active worker, an attachment, forwarded mail, notes, a scheduled reminder, and a recurring task with a run history. The baseline is `5511dba`. Screenshots and measurement reports are under `/workspace/tmp/hearth-qa/run39/`.

ChatGPT’s mobile history provides a benchmark for quiet thread rows and predictable drawer navigation. Claude’s artifact workflow sets the bar for clear previews and recovery. Hark’s Home panels and contextual actions inform the Home hierarchy. Hearth keeps its own visual language, with Ember in the chat header and room for activity, approvals, and memory. [ChatGPT mobile](https://help.openai.com/en/articles/8142208), [Claude artifacts](https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them), [Using Hark Pro](https://hark.com/using-hark)

The browser pass covered the drawer and header, Home layout and health, chat and message actions, attachments and file cards, Skills, workers and Stop, approvals, dictation feedback, Call, Timeline, Artifacts and Pages, Reminders and recurring tasks, Inbox and mail source, all five Memory areas, and all Settings disclosures. It also covered representative empty, loading, and error states, toasts, menus, dialogs, keyboard focus, reduced motion, long text, and dark and light palettes. The touch requirement is 44×44 CSS pixels for standalone controls. The contrast sweep samples rendered text, placeholders, icons, relevant control boundaries, and focus rings against WCAG AA thresholds. Intrinsically wide document content can scroll within its preview. [WCAG 2.2](https://www.w3.org/TR/WCAG22/)

## Verification boundaries

WebKit emulation exercised the keyboard code with a resized visual viewport and checked keyboard dismissal, focus restoration, and scrollable panes. Physical iPhone Safari address-bar transitions, cutout insets, VoiceOver announcements, and microphone hardware remain unverified. The browser fixture used a scripted call and an unavailable dictation engine to review voice feedback. The comparison used the products’ published workflows. [WebKit dynamic viewport units](https://webkit.org/blog/12445/new-webkit-features-in-safari-15-4/)

## Results

- The audit found no P0 issues. All six P1 fixes and five P2 fixes are in place. Three P2 items remain open.
- All 196 Python tests and eight Node tests passed. The WebKit matrix found zero pane overflow or undersized standalone touch targets and zero failures in 31,155 sampled contrast measurements. The Chromium contrast suite passed 16,299 measurements. Dedicated browser suites passed Skills editing and chat links, worker Stop, Pages, For you, and drawer and Settings navigation.
- `scripts/deploy.sh` completed. The live `/health` returned HTTP 200 with Sprite checkpoints. All 38 deployed static assets matched by SHA-256, and the running server served the matching HTML.
- Live WebKit at 390×844 dark rendered all nine destinations, including the Pages filter, recurring tasks, all five Memory areas, and all 11 Settings disclosures. The TCP proxy reset, so the smoke check used a loopback relay over Sprite exec with requests against the running service. The Timeline event stream was exercised by the local fixture. The live check captured no workspace screenshots.
