# Run 97 · Chat flicker

The offline fixture reproduced message replacement on every send, a welcome-screen flash when opening chats with saved messages, and a scroll jump when a reply advanced the latest-message window. The Chat view and transcript roots kept their identity in every scenario.

## Causes and fixes

- **Message identity during streaming.** In `chat/workspace.js`, each render of a pending turn allocated new Preact keys. The optimistic user row was replaced on `queued`, `started`, `done`, stream cleanup, and the state refresh. The assistant row was replaced on `done`, cleanup, and refresh. All four profiles recorded eight row removals for one send, including six pairs with matching content. The prompt and assistant now keep their keys through those transitions, including when a poll sees the saved reply before the receipt arrives. `chat/conversation.js` keeps the message body and plain-text paragraph in place and renders rich Markdown inside the same bubble. The repeat recorded two row additions and zero removals or same-content transcript replacements.
- **Empty-state flash on thread entry.** `renderChat()` treated the pending snapshot like an empty thread. After the cold Chat module loader closed, Main showed its welcome for 204–362 ms before its saved messages appeared. Switching back to populated Main showed it for 190–310 ms. Opening the 500-message side chat showed its welcome for 270–779 ms. Both welcome states now wait for a snapshot. Every populated entry recorded zero welcome flashes. The empty side chat still showed its welcome after its snapshot arrived.
- **Scroll position at the history boundary.** `advancePages()` kept the old window only after the reader had explicitly loaded an older page. A remote turn moved two rows out of the latest 50 and removed the row in view. An automatic older-page fetch then reinserted the two rows and brought in 48 more. Chromium recorded a shift of 0.14939 on mobile and 0.03729 on desktop. WebKit briefly reset `scrollTop` from 80 px on mobile and 65 px on desktop to zero. Chat now archives the overlapping window when the reader is above the bottom and keeps its earlier-page cursor through metadata refresh. All four profiles kept the same message at the same offset through the arrival, with zero row removals. Later, explicitly loading older history still prepended the contiguous 50 rows.
- **Recurring updates with no visible change.** The avatar interval rewrote the already-hidden caption about ten times per second. A minute of idle Chat produced 577–598 caption mutations across the four profiles. The caption now updates on a visibility change. The reply-clamp effect also scanned every mounted expand control once per reply on a long-thread open. Opening its first 50 rows produced 650 hidden-attribute records on expand controls in each profile. The render now checks those controls once, with a local check on expansion. Both redundant writes dropped to zero.

## Offline browser measurements

Chromium 159.0.8154.6 ran with normal motion. Playwright WebKit 27.2 ran with reduced motion under GTK and Xvfb after its normal-motion navigation crashed locally. Each engine ran a 390 × 844 mobile touch context and a 1440 × 900 desktop context. These runs used loopback Python servers, disposable data, Mock replies, and a browser route guard for external requests. The fixture paced the Mock tokens and the final receipt, disabled idle module prefetch for the cold Chat visit, and added 250 ms to the cold module request and 160 ms to state requests to expose transient screens.

Mutation observers watched the app subtree and the transcript. Direct transcript child removals counted lost message nodes. Matching a removed and added node by tag, class, and normalized text counted same-content replacements. Root identity and visibility were tracked independently. - The send window contained 17 transcript-node additions and eight removals before the fix, and five additions and two removals afterward. The remaining removals were the queued label and the typing dots. The 60-second idle runs completed about five state polls each and recorded zero transcript mutations throughout. The few app records after the fix came from history navigation visibility writes on state responses.
- Cold Home → Chat showed one workspace loader in each build. Warm Home → Chat, send through completion, idle polling, and thread switches produced zero workspace loader flashes. Switching threads replaced the expected message rows. No run replaced the app, Chat view, or transcript root.
- After older history was loaded, both the remote reply and the reply from the local stream preserved the visible message and its offset while the reader stayed above the bottom. The local send initially followed the composer, then the test scrolled up during the reply.
- Chromium's `PerformanceObserver` reported four shift entries around send, totaling about 0.00206 on mobile and 0.00026 on desktop on both builds. They came from the Stop control changing the composer grid and typing indicator movement. The remote window rollover shift dropped to zero on both viewports. These are per-scenario sums, including any entries marked as recent input. WebKit did not expose `layout-shift`, so its comparison used DOM identity and measured scroll geometry.
